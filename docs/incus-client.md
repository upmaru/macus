# The shared Incus client

Macus's typed Incus client is the shared
[`:opsmaru_incus`](https://github.com/upmaru/opsmaru-incus) Hex package,
locked in `server/mix.lock`. Macus implements no Incus client, codec, model,
version check or native error handling of its own. It supplies the backend
and the trust decisions; the library does the rest.

## How Macus binds the library

`:opsmaru_incus` is a pure library: it has no application callback, so it
starts no process, listener, state or backend connection, and `PHX_SERVER`
or `PORT` change nothing. Macus passes every backend explicitly
(`Macus.MCP.IncusHost`):

- **Connection.** Always the owner's `<state-dir>/incus.sock`, from trusted
  configuration. No tool input, URL or member name can select another
  backend.
- **Context.** The verified owner and caller identity, plus a readiness
  check the library runs before every request. The check needs the serving
  gateway and an owner-private `incus.sock` in an owner-private directory.
  Until it passes, every call fails with `host_not_ready` and nothing is
  sent.
- **Client workers.** With the serving gateway, Macus starts the library's
  optional `Opsmaru.Incus.ClientSupervisor` as `Macus.Incus.Clients`, by
  default with 16 workers (`config :macus, Macus.Incus, client_workers: n`,
  or `false` for none). `Macus.Incus.run/3` runs client work there. A call
  at capacity fails at once; there is no queue. Starting or restarting the
  workers opens nothing, does no recovery work and never starts, stops or
  deletes the VM or its workloads. A lost worker or a local deadline does
  not cancel work Incus may already have accepted, and nothing is retried.

The MCP Incus operations use the same connection and context. Neither the
operation index nor the MCP endpoint is needed for client work.

## Coverage

The library maps each declaration of the pinned official Incus Go client to
an implementation and its own test evidence. Macus reads that record from
the locked package (`Macus.Incus.Coverage`) and publishes it as
[the coverage page](incus-coverage.md), generated by
`mix macus.incus.coverage`. A test fails when the page no longer matches
the locked package.

Two claims are kept apart, as the library keeps them:

- **Behaviour** (task 6.12). `Macus.Incus.Coverage.behavior_errors/3` must
  find nothing: every documented Incus endpoint pair behaviour-complete under
  a reviewed completion record, every streaming contract certified, the
  selected evidence complete for every pair, one Incus reference, and every
  Incus operation in the MCP catalogue naming requirements that pass the
  library's `Opsmaru.Incus.Operations.Evidence.lookup/1` with library (not
  relay or Macus) evidence. This holds for the locked package.
- **Go declaration parity.** The library is **not a complete port** of the
  Go client: it says so itself, and every declaration is partial or missing.
  `Macus.Incus.Coverage.complete_port?/0` is true only when the library claims
  a complete port **and** every inventory declaration is `complete` with an
  implementation and library evidence. A claim alone is not enough. Macus
  makes no such claim and does not need one.

Either way, missing support is never filled by a Macus implementation.

Native gateway relay tests (the library's `test/gateway_*`) and Macus's own
tests never count as typed-client evidence. Relaying a native request proves
the proxy, not the client.

## Linked evidence

The library's evidence is linked, not rerun: `Macus.Incus.Evidence`
(`mix macus.incus.evidence`, `--check`) verifies for the locked package that
the Hex version and checksum in `server/mix.lock` equal the loaded package's
own version and source, that every record under `priv/incus` that pins the Incus
reference agrees with `reference.json`, that the records hash to the
package's own `transfer.json`, that complete coverage claims ship real
implementations, and that every Macus binding (connection, files, streams,
sessions, and every MCP `search`/`execute` operation) maps to library
evidence that the library does not mark unavailable. The check also reads
the calls out of Macus's own compiled modules, so every library call its
production code makes is covered by a binding entry, and an entry never
lists a call no Macus code makes. Four evidence classes
stay machine-checked distinct, and substituting one for another fails:

| Class | What it is | Never counts as |
| --- | --- | --- |
| Library | The evidence the package ships, at the locked reference | Guest or hardware acceptance |
| Consumer | Macus's binding tests over its own `incus.sock` | Library coverage or conformance |
| Relay | Gateway relay fixtures, library `test/gateway_*` and Macus's `server/test/macus/proxy/` | Library conformance or coverage |
| Hardware | Real guest workloads through an installed Macus | Never claimed by any other class's success |

The summary is published as [the linked-evidence page](incus-evidence.md),
generated by `mix macus.incus.evidence`; a test runs `--check` with every
`mix test`.

## Who owns which evidence

| Evidence | Owner | Where |
| --- | --- | --- |
| Client implementation, codecs, models, native errors and their coverage against the pinned reference | opsmaru_incus | Its tests and `priv/incus/coverage.json`, at the locked version; linked and checked by `Macus.Incus.Evidence`, never rerun or duplicated |
| Reference pin, declaration inventory and its generator | opsmaru_incus | `priv/incus/reference.json` and `inventory.json`; the generator in its repository |
| Macus's binding: owner-bound `incus.sock`, readiness, owner checks, deadlines, typed results, native errors and extension checks through that binding | Macus | `server/test/macus/incus/` |
| Native gateway relay through the Macus listener, with the official client | Macus | `server/test/macus/proxy/` and `server/test/macus/incus/reference_wire_test.exs` |
| Real guest workloads through an installed Macus | Macus hardware acceptance | [Acceptance](acceptance.md); opt-in, never replaced by fixture success |

Library fixture success never completes Macus hardware acceptance.

## Transferred fixtures

Macus produced the first Incus reference pin, declaration inventory,
inventory generator, wire cases and HTTP fixtures. They moved to
opsmaru_incus with their notices; its `priv/incus/transfer.json` records
each file's Macus source hash and transferred hash. Macus now reads the
reference pin and inventory from the locked package and no longer carries
its own copies, generator or inventory diff.

Macus keeps the fixtures that test its own relay and binding: the native
wire cases (`server/test/fixtures/incus/wire.json`), the official-client
reference driver (`server/test/reference`, extended for Macus's
differential checks), and the HTTP, TLS and wire-comparison helpers in
`server/test/support`. Their Incus attribution is in
`server/priv/notices`.

## Updating the dependency

1. Before changing `server/mix.lock`, save the current
   `deps/opsmaru_incus/priv/incus/inventory.json` outside the repository.
2. Update the lock to the new released version (Hex only; never a Git
   revision or sibling checkout).
3. Run `mix macus.incus.coverage --diff <saved inventory>` from `server/`. It
   lists every added, removed and changed declaration, including changed
   source files.
4. Run `mix macus.incus.coverage` and `mix macus.mcp.manifest`, and review
   both diffs before describing the new version as supported.
5. Rerun the consumer checks: `server/test/macus/incus/`, the proxy tests
   and the MCP tests. Changed declarations that Macus uses need their
   consumer evidence rerun; hardware acceptance stays separate.
