## 1. Prerequisites and qualification spike

- [x] 1.1 Get an `opsmaru-containers` release that packages `Opsmaru.Containers.Transport.ExecBridge` with the helper source, the split raw entry (`Raw.open/3`, `Raw.run/4`), the optional same-listener `Docker.CowboyHandler` with a `fallback` handler, and request and exchange telemetry. Released as `opsmaru_containers` 0.2.0 on Hex (2026-11-26, change `add-cowboy-gateway-embedding`, upmaru/opsmaru-containers#6 and #8). Hex checksum `e2e27dc732c3efe35b6a09dc5e78f1c4cbf6681b6ae522c7d12eeeea5687d510`, built by the release workflow from merge commit `c5623b9` and verified against the public release. It requires `opsmaru_incus ~> 0.2.10`, with `cowboy ~> 2.12`, `plug ~> 1.16` and `telemetry ~> 1.3` optional. Its tasks 2.5 (TLS half-close measurement of the pinned CLI) and 3.5 (real-Incus rerun of the packaged bridge) were open at release. Macus depends only on the released package.
- [x] 1.2 Spike on isolated state, with explicit opt-in, against a disposable engine. Mount the Docker route set on a scratch build of the gateway listener and qualify each item below. Record the observed requests and results. If half-close fails, return this change to planning (design decision 8). Run it after the library records its measurement of the pinned CLI's TLS half-close (its task 2.5). If the shared listener shows a route collision or Cowboy constraint, switch to the decision 1 fallback in the design before task 3.
  - Go `close_notify` half-close over Erlang `:ssl` TLS 1.3, in both directions: `docker exec -i CONTAINER sh -c 'cat; echo done'` with redirected stdin must print `done` (upstream evidence predicts it will not)
  - closing an active raw relay on certificate revocation, from outside the library-owned relay process
  - the pinned CLI's `Upgrade` headers on attach and exec start
  - BuildKit `/grpc` and `/session` with `h2c` through Cowboy `switch_protocol` and takeover
  - Go's acceptance of the gateway certificate as `ca` for `127.0.0.1`
  - Run on 2026-11-27 on isolated state (gateway `127.0.0.1:60542`, own `INCUS_CONF` and `DOCKER_CONFIG`) with a scratch gateway build from the local branch `feature/docker-engine-spike` at `40213b0`. Stack: `opsmaru_containers` 0.2.0, opsmaru_incus 0.2.10, OTP 27 (erts 15.2.7.12), Incus 7.0.1, engine `images:debian/13` arm64 with Docker Engine 29.10.0 (API 1.57), containerd 2.4.2 and the packaged bridge helper (SHA-256 `b689ab97…`, matching the library README). Client: Docker CLI 29.10.0 darwin/arm64, Compose 5.8.0, Buildx 0.39.1. The evidence and report are kept in the ignored `.integration/docker-spike/`.
  - **Half-close: fails, more broadly than predicted.** `docker exec -i C sh -c 'cat; echo done'` with redirected stdin exited 0 and printed nothing in three runs. Each exchange got `101`, delivered all 12 input bytes to the engine, returned 0 bytes and ended `caller_closed`. `docker exec C sh -c 'echo hello'` without `-i`, `docker run --rm IMG sh -c 'echo …'` and `docker run --rm -i` also exited 0 with no output, and `docker attach` with redirected stdin failed with `unexpected EOF`. With stdin held open, output arrived until stdin EOF and was lost after it. The same command run on the engine without the gateway printed everything. The CLI reports success while losing output. Whether the CLI half-closes with `close_notify` or a TCP write shutdown was not captured. **The gate fails, and this change returns to planning (design decision 8).**
  - **Revocation of an active raw relay: no handle.** Killing the Cowboy request process registered for a raw exec did not end the stream. Output kept arriving until the client stopped. After takeover the relay runs in a library-owned process that Macus cannot reach.
  - **`Upgrade` headers:** exec start and attach were taken by `Docker.CowboyHandler` with `101`, so the pinned CLI sends `Upgrade` on both. The exact values were not logged.
  - **BuildKit:** `POST /grpc` and `POST /session` with `h2c` were taken over with `101`. `docker buildx build` failed with `no local sources enabled` after the `/session` stream ended `caller_closed`. The cause was not isolated.
  - **Gateway certificate as `ca`:** the context reached the engine for `127.0.0.1` with no TLS override.
  - **Shared listener:** no route collision or Cowboy constraint. Incus and Docker worked on the same port, and the raw path saw each connection's client certificate through `:cowboy_req.cert/1`.
